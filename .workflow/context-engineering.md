# 컨텍스트 엔지니어링 가이드

이 문서는 AI 에이전트가 효율적으로 작업할 수 있도록 컨텍스트를 최적화하는 방법을 설명합니다.

## 🎯 목적

컨텍스트 엔지니어링의 목적은 AI 에이전트가 작업에 필요한 최소한의 정보만 사용하여 효율적으로 작업할 수 있도록 하는 것입니다. 이를 통해 토큰 사용량을 최적화하고, 작업 속도를 향상시키며, 더 정확한 결과를 얻을 수 있습니다.

## 📋 핵심 원칙

### 1. 문서 우선 접근

- **작업 전**: 관련 문서를 먼저 확인
- **도메인 문서 확인**: `.workflow/domain-*.md` 파일을 먼저 읽기
- **불필요한 스캔 방지**: 전체 코드베이스를 grep하지 않기

### 2. 최소한의 컨텍스트 사용

- **필요한 파일만 읽기**: 작업과 직접 관련된 파일만 확인
- **전체 파일 읽기 지양**: 필요한 부분만 읽기
- **중복 정보 제거**: 이미 문서화된 정보는 다시 읽지 않기

### 3. 구조화된 정보 활용

- **도메인별 구조 문서**: 각 도메인의 API, 컴포넌트 구조를 문서로 확인
- **아키텍처 문서**: 전체 시스템 구조는 별도 문서로 확인
- **타입/데이터 구조**: 데이터 모델은 문서로 확인

## 🔍 작업 시 컨텍스트 수집 전략

### 새 기능 추가 시

1. **도메인 문서 확인** (`.workflow/domain-*.md`)
   - 관련 도메인의 API 구조 파악
   - 기존 패턴 확인
   - 데이터 구조 이해

2. **관련 파일만 확인**
   - 도메인 문서에서 언급된 파일만 읽기
   - 전체 디렉토리 스캔 지양

3. **최소한의 변경**
   - 기존 패턴을 따르기
   - 불필요한 리팩토링 지양

### 버그 수정 시

1. **관련 도메인 문서 확인**
   - 문제가 발생한 도메인 파악
   - 해당 도메인의 구조 문서 확인

2. **문제 발생 지점만 확인**
   - 에러 메시지나 로그를 기반으로 특정 파일만 확인
   - 전체 코드베이스 스캔 지양

3. **최소한의 변경**
   - 문제 해결에 필요한 최소한의 변경만 수행
   - 관련 없는 부분은 건드리지 않기

### 리팩토링 시

1. **영향 범위 파악**
   - 도메인 문서를 통해 영향 범위 확인
   - 관련 파일 목록 작성

2. **단계별 진행**
   - 한 번에 하나의 도메인만 리팩토링
   - 각 단계마다 문서 업데이트

## 📚 문서 우선순위

### 1순위: 도메인별 구조 문서

- `.workflow/domain-scraping.md` - 스크래핑 도메인
- `.workflow/domain-web.md` - 웹 서비스 도메인

**이유**: 가장 구체적이고 작업에 직접 필요한 정보를 포함

### 2순위: 아키텍처 문서

- 전체 시스템 구조 이해
- 컴포넌트 간 관계 파악

### 3순위: 타입/데이터 구조 정의

- Pydantic 모델 정의
- 데이터베이스 스키마

### 4순위: 코드 파일

- 문서에서 확인할 수 없는 세부 구현만 확인
- 가능한 한 코드 파일 직접 읽기 지양

## ⚠️ 피해야 할 것들

### ❌ 하지 말아야 할 것

1. **전체 코드베이스 grep**
   - 특정 키워드로 전체 검색
   - 불필요한 파일까지 스캔

2. **관련 없는 파일 읽기**
   - 작업과 직접 관련 없는 파일 읽기
   - "혹시 몰라서" 읽는 파일들

3. **중복 정보 수집**
   - 이미 문서화된 정보를 코드에서 다시 확인
   - 같은 정보를 여러 곳에서 확인

4. **전체 파일 읽기**
   - 필요한 부분만 있는데 전체 파일 읽기
   - 큰 파일을 처음부터 끝까지 읽기

### ✅ 해야 할 것

1. **도메인 문서 먼저 확인**
   - 작업 전 관련 도메인 문서 읽기
   - 구조와 패턴 파악

2. **필요한 부분만 읽기**
   - 특정 함수나 클래스만 확인
   - 파일의 일부만 읽기

3. **문서 업데이트**
   - 코드 변경 시 관련 문서도 업데이트
   - 다음 작업을 위한 컨텍스트 준비

## 💡 실전 예시

### 예시 1: 새 API 엔드포인트 추가

**잘못된 방법:**
```
1. 전체 프로젝트 grep으로 "api" 검색
2. 모든 API 파일 읽기
3. 전체 라우팅 구조 파악
```

**올바른 방법:**
```
1. domain-web.md에서 API 구조 확인
2. 기존 API 파일 하나만 참고
3. 동일한 패턴으로 새 API 추가
```

### 예시 2: 데이터베이스 모델 수정

**잘못된 방법:**
```
1. 전체 프로젝트에서 모델 사용처 검색
2. 모든 관련 파일 읽기
3. 전체 영향 범위 파악
```

**올바른 방법:**
```
1. domain-scraping.md에서 데이터 구조 확인
2. models.py에서 해당 모델만 확인
3. Repository 패턴 확인
4. 최소한의 변경만 수행
```

## 📊 토큰 사용량 최적화

### 효율적인 컨텍스트 수집

- **도메인 문서**: ~500-1000 토큰
- **관련 파일 일부**: ~200-500 토큰
- **총합**: ~700-1500 토큰

### 비효율적인 컨텍스트 수집

- **전체 코드베이스 grep**: ~5000-10000 토큰
- **관련 없는 파일 읽기**: ~2000-5000 토큰
- **총합**: ~7000-15000 토큰

**절약 효과**: 약 10배 토큰 절약 가능

## 📝 체크리스트

작업 전 확인:

- [ ] 관련 도메인 문서 확인했는가?
- [ ] 필요한 파일 목록을 정리했는가?
- [ ] 불필요한 파일을 제외했는가?

작업 중:

- [ ] 문서에서 확인할 수 있는 정보를 코드에서 다시 확인하지 않았는가?
- [ ] 필요한 부분만 읽고 있는가?
- [ ] 전체 파일을 읽지 않고 있는가?

작업 후:

- [ ] 관련 문서를 업데이트했는가?
- [ ] 다음 작업을 위한 컨텍스트를 준비했는가?
